
## 無人ループ（hootl）で動いているとき

環境変数 `HOOTL_TASK_ID` が設定されているときは、無人のループで1タスクだけを担当している。人は不在で、質問には誰も答えない。このときは、この CLAUDE.md の他の節（ブランチ戦略・エージェント活用など）より、次のルールを優先する。

### やってよいこと（必要なら迷わずやる）

- 依存パッケージの追加・更新、`package.json` の編集
- 設計判断の記録（`docs/decisions/`）
<!-- RUNBOOK 手順 5: DB を使うプロジェクトなら、ここにスキーマ変更の扱いを書く。Prisma の例:
- `prisma/schema.prisma` の変更と `npx prisma db push`、続けて `npx prisma generate`（接続先は使い捨てのテスト用 DB。毎回リセットされる）。`--force-reset` と `--accept-data-loss` は AI エージェントからは Prisma が実行を拒否するので使わない（データが消える変更はゲートが反映する）
-->

依存を足したりスキーマを変えたりしたら、理由を `docs/decisions/NNNN-<slug>.md` に1〜3行で残す（レビューが妥当性を判断する材料になる）。

### やってはいけないこと（機械的に検出されて差し戻される）

- テストの `skip` / `only` / `todo` の追加、既存テストの削除
- 型チェック・lint の抑止コメント（`@ts-ignore` / `@ts-expect-error` / `eslint-disable` / `biome-ignore`）の追加
- 判定する側のファイルの変更: <!-- RUNBOOK 手順 5: hootl.toml の protected_paths に合わせて列挙する -->
- コミット・push・ブランチ操作（ハーネスが行う）

### 進め方

1. 受け入れ条件1つにつき、少なくとも1つのテストを書く。テスト名に `<タスクID> AC<番号>` を入れる。
2. 時刻と乱数は引数で注入できるようにする。テストでは固定値を渡す。
3. タスクの「主に変更するパス」を基本にする。それ以外を変える必要があれば変えてよいが、理由を `docs/decisions/` に残す（説明のない範囲外の変更は差し戻される）。
4. 判断できないことは推測で埋めない。`docs/decisions/` に「判断不能: 〜」と書いて終える。
5. 終わる前に、プロンプトに書かれたゲートを全部実行し、通ることを確認する。

仕様は `spec.md`、無人開発の標準は hootl-sdd の `docs/dev-standards.md` に従う。
