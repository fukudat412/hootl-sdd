hootl

管理画面へ

使い方

作りたいものを数行書くと、エージェントが仕様を書き、タスクに分け、実装して、テストとレビューを通ったものだけを main に入れます。人がやるのは「何を作るか決める」「朝に要対応を見る」「外へ出す」の3つです。

  • 起動する・入る
  • 作る（おまかせ）
  • 進み具合・止める
  • ネタ帳
  • 要対応が出たら
  • 計画と承認
  • 新しいアプリ
  • 設定
  • 困ったとき

起動する・入る

  1. 起動: Finder で hootl-sdd フォルダの hootl-start.command をダブルクリック（再起動も同じ）。Mac にログインすれば自動でも起動しています。
  2. 開く: http://127.0.0.1:8765
  3. トークン: ターミナルで下のコマンドを実行すると、クリップボードに入ります。ログイン画面に貼り付けて「入る」。
hootl token

画面に文字として出したいときは hootl token --show。hootl-start.command を実行したときも、クリップボードに入ります。中身は ~/.config/hootl/web.toml の token です。一度入れば、そのブラウザでは30日間聞かれません。

作る（おまかせ）

  1. 上でプロジェクトを選び、「仕様」タブを開く。
  2. 「新しく作りたいもの」に、思いついたことを数行書く。例: 「間違えた過去問だけを、もう一度解ける復習モードがほしい」
  3. 「おまかせで作る」を押す。ここから先は、承認を挟まずに進みます。
段起きること
仕様エージェントがコードと今の仕様を読んで、仕様を書く。決めきれない点は自分で決めて、「自分で決めたこと」に理由つきで残す
凍結specs/ に入れて main にコミットする
計画1件ずつ実装できるタスクに分ける
取り込み機械で確かめて「待ち」に入れる。通らなければ「計画と承認」に残す
実装1件ずつ、実装 → 安全柵 → ゲート → レビュー → マージ。落ちたら理由を添えて最大3回やり直す

自分で読んでから進めたいときは「下書きだけ作る」。下書きを開いて直し、「凍結して、あとはおまかせ」か「凍結してタスク案まで」を押します。

進み具合・止める

  • 上のライン: 待ち → 準備 → 実装 → 安全柵 → ゲート → レビュー → マージ → 完了。いま各工程にいるタスクが出ます。
  • その下の箱: おまかせがいまどの段か（仕様・凍結・計画・取り込み・実装）。「出力の末尾」を開くと、直近の記録が読めます。
  • 止める: 実装の段では「今のタスクで止める」（動いているタスクを終わらせてから止まる。もう一度押すとすぐ止まる）。その前の段では、すぐ止まります。
  • タスクタブ: 行を押すと、中身・受け入れ条件・試行ごとのログと差分が読めます。
  • レポートタブ: ランが終わるたびに1本。完了・要対応・ネタ帳に増えた案が並びます。
  • 回す: 「待ち」が残っているときに、時間と並列を選んで手で回せます。

ネタ帳

エージェントが、仕様づくり・計画・実装・レビューの途中で気づいた「今回は作らないが、よさそうな案」がたまります。たまるだけで、勝手には作りません。タブに新しい案の件数が出ます。

  • これを作る（2回押し）: その案を「作りたいもの」として、おまかせで実装まで進めます。
  • 捨てる: 一覧から下げます。「これまでの案」から戻せます。同じ名前の案は、もう拾いません。
  • 自分で足す: 思いついたことのメモ置き場にも使えます。何かが動いている最中でも足せます。

要対応が出たら

3回やり直しても通らなかったタスクは、ラインから外れて「要対応」になります。ほかのタスクは止まりません。

  1. 「タスク」タブの一番上にある要対応の行を押す。
  2. 理由と、試行ごとのログ（実装・ゲート・レビュー・差分）を読む。
  3. 原因が環境（依存・ポート・ログイン切れ）なら、直してから「やり直す（待ちに戻す）」。
  4. タスクそのものが大きすぎる・あいまいなら、作りたいものを書き直して、もう一度おまかせで作る。

計画と承認

おまかせでは、ここを通りません。タスク案が並ぶのは次のときだけです（タブに ● が付きます）。

  • 機械の確認で止まった（すでにある ID と重なる・ないタスクに依存している・依存が輪になっている・1つの仕様から20件を超えた）
  • 「凍結してタスク案まで」や「この仕様からタスク案を作る」で、自分で読むことにした

カードで読み、「タスク案を直す（JSONL）」で直して保存し、「承認して取り込む」（2回押し）。要らなければ「この案を捨てる」。

承認待ちのタスク案が残っている間は、次のおまかせを始めません（上書きして失わないため）。取り込むか捨てると、また始められます。

新しいアプリ

上の「＋ 新しいアプリ」から。作りたいもの・名前・型（Web／スマホ／バッチ／Cloudflare Workers）・オプション・ゲートを選んで「作る」。フォルダ・git・依存・全ゲート・起動確認・最初のコミットまで進みます（数分）。

作りたいものを書いておくと、できあがったあと、そのまま仕様 → 計画 → 実装まで続きます。下書きで止めたいときは「できたら、そのまま実装まで進める」を外します。

エージェントは、そのアプリのフォルダの外を読めません。参考にしてほしい資料は、アプリの中（例: materials/）に置いてください。

設定

「設定」タブで、場所・型・レビュー役・おまかせの状態が見られます。カタログから作ったアプリは、使うゲートをここで切り替えられます。

おまかせの動きは、プロジェクトの hootl.toml に [auto] を書いて変えます（書かなければ、下の既定）。

キー既定中身
approvetruefalse にすると、仕様の下書きとタスク案で止まり、自分で承認する
runtruefalse にすると、「待ち」に入れたところで止まる（回すのは自分で押す）
hours7おまかせで回す時間の上限。0 で、空になるまで
max_tasks201つの仕様からこれより多く出たら、取り込まずに人に回す

困ったとき

症状見る所・直し方
まず何を見るかターミナルで hootl doctor（道具・設定・プロジェクト・画面の応答を一覧する）
画面が開かないhootl-start.command をダブルクリックし直す
トークンが分からないhootl token（クリップボードに入る）
おまかせが途中で止まった箱の「出力の末尾」に理由が出ます。仕様で止まったら「仕様」タブの下書き、取り込みで止まったら「計画と承認」から続けられます
「承認待ちのタスク案が残っています」「計画と承認」で取り込むか捨てる
「未コミットの変更があります」回す専用の clone（「設定」タブの「場所」）を手で触っています。コミットするか元に戻す
始めてすぐ終わる・全部が要対応「出力の末尾」とタスクのログを読む。command not found や古い Node なら、普段のターミナルから hootl-start.command を実行し直す
寝ている間に止まるMac がスリープしています。電源につなぎ、ディスプレイがオフでもスリープしない設定にする
