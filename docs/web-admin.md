# Web 管理画面の動かし方

スマホから hootl に作りたいものを書き、進み具合を見て、止めて、やり直すための画面。仕様とタスク案の承認は挟まない（おまかせ）。作業中に見つかった案は「ネタ帳」にたまる。仕組みの全体像は `docs/how-it-works.html`（ブラウザで開く）。

## 始め方（1コマンド）

Finder で `hootl-start.command` をダブルクリックしてもよい（Python 3.11 以上を探して `hootl setup` と `hootl doctor` を流す。何度やってもよいので、再起動にも使える）。

```bash
cd ~/hootl-sdd && python3 -m pip install -e '.[dev]'   # 初回だけ
hootl setup
```

`hootl setup` がやること（何度実行してもよい。あるものは残し、足りないものだけ作る）:

1. 道具を確かめる（python・git・claude・codex・node・docker）。足りなければ入れ方を出して止まる
2. `~/.config/hootl/web.toml` を作る。トークンを作り、権限を 600 にする。2回目以降はトークンを作り直さない
3. `~/hootl-runs/` の下の `<名前>/hootl.toml` をプロジェクトとして拾う。**専用 clone を増やすと、設定を直さなくても画面に出る**
4. Mac にログインしたら自動で起動するよう登録する（launchd）。いまのターミナルの PATH をそのまま渡すので、中で claude・codex・node が見つかる
5. トークンをクリップボードに入れ、ブラウザで http://127.0.0.1:8765 を開く（貼り付けて入る）

### スマホからも使う

```bash
hootl setup --email 自分のメールアドレス --hostname hootl.example.com
```

1回目は Cloudflare Access（門番）の作り方を出して止まる。**門番ができるまで、外への公開（DNS とトンネル）は始めない。** ダッシュボードで Access を作ったら、`--access-ready` を足して同じコマンドをもう一度:

```bash
hootl setup --email 自分のメールアドレス --hostname hootl.example.com --access-ready
```

ここで、Cloudflare へのログイン（初回だけブラウザが開く）、トンネルの作成、DNS、トンネルの自動起動までが済む。スマホで https://hootl.example.com を開き、メールのコード → トークンの順で入る。

### 起動する・トークンを出す

- 起動（再起動も同じ）: Finder で `hootl-start.command` をダブルクリック。Mac にログインすれば自動でも起動している
- 開く: http://127.0.0.1:8765
- トークン: `hootl token` でクリップボードに入る（ログイン画面に貼る）。画面に出したいときは `hootl token --show`。`hootl-start.command` を実行したときもクリップボードに入る。中身は `~/.config/hootl/web.toml` の `token`
- 一度入れば、そのブラウザでは30日間は聞かれない
- 使い方: 画面右上の「使い方」（`/help`）。ログイン画面からも開ける（トークンなしで読める。秘密は載っていない）。仕組みの図解（`docs/how-it-works.html`）もそこから開く

### 状態を確かめる

```bash
hootl doctor
```

道具・設定ファイルの権限・メールの照合・見つかったプロジェクト・画面が応答しているか・トンネルの設定を一覧する。

### 寝ている間も動かすとき

- システム設定 → バッテリー → オプション → 「電源アダプタ接続時、ディスプレイがオフのときに自動でスリープさせない」をオン
- 蓋は開けておく（閉じるとスリープする。外部ディスプレイ＋電源つなぎっぱなしなら閉じてもよい）

## できること・できないこと

| 画面 | できること |
| --- | --- |
| 上のライン | 待ち → 準備 → 実装 → 安全柵 → ゲート → レビュー → マージ → 完了。いま各工程にいるタスクと件数。要対応の件数 |
| 回す／止める | 時間（1〜10時間・空になるまで）と並列（1〜4本）を選んで回す。「今のタスクで止める」は、動いているタスクを終わらせてから止まる。もう一度押すと、すぐ止める |
| タスク | 要対応 → 実行中 → 待ち → 完了。開くと、中身・受け入れ条件・試行ごとのログ（実装・準備・ゲート・レビュー・差分）。要対応は「やり直す」で待ちに戻せる |
| 回す箱（おまかせ中） | いまの段（仕様 → 凍結 → 計画 → 取り込み → 実装）。「止める」は、実装の段なら今のタスクを終わらせてから、その前の段ならすぐ止まる。機械の確認で止まったときは、理由が「出力の末尾」に出る |
| 仕様 | 作りたいものを数行書く →「おまかせで作る」。エージェントが仕様を書き、`specs/<日時>.md` として main にコミット（凍結。push 先があれば push）し、タスクに分け、確かめて取り込み、回すところまで進む。自分で読みたいときは「下書きだけ作る」→ 直して「凍結して、あとはおまかせ」か「凍結してタスク案まで」（どちらも2回押し）。凍結した仕様は後から読める・もう一度タスク案を作れる |
| ネタ帳 | エージェントが仕様づくり・計画・実装・レビューの途中で見つけた「今回は作らないが、よさそうな案」。どの作業中に出たかと中身を読み、「これを作る」（2回押し。おまかせで実装まで進む）か「捨てる」。自分のメモも足せる。たまるだけで、勝手には作らない。タブに新しい案の件数が出る |
| 計画と承認 | おまかせでは通らない。ここに並ぶのは、機械の確認で止まったタスク案（タブに ● が付く）と、自分で読みたくて作った案。カードで読み、JSONL で直して保存し、「承認して取り込む」（2回押しで確定）か「この案を捨てる」。取り込んだ案は `.hootl/imported-<日時>.jsonl`、捨てた案は `discarded-<日時>.jsonl` に控えが残る |
| レポート | ランごとのレポート（直近20本） |
| 設定 | 場所・型・オプション・レビュー役・おまかせの設定。カタログから作ったアプリは、ゲートを切り替えて main にコミットできる |
| ＋ 新しいアプリ | 作りたいもの・名前・型（Web／スマホ／バッチ／Cloudflare Workers）・オプション・ゲートを選んで「作る」。git・依存・全ゲート・起動確認・最初のコミット・仕様の下書きまで進み、「できたら、そのまま実装まで進める」が付いていれば（既定）凍結 → 計画 → 実装まで続く（`docs/new-app.md`） |

できないこと: 任意のコマンドの実行（ゲートの中身もカタログにあるものだけ）、ファイルの読み書き（決まったログを読むだけ）、完了や実行中のタスクの巻き戻し、push の取り消し。

### 新しく作りたいものができたとき

spec.md を手で書き足す必要はない。「仕様」タブに思いつきを書けばよい。

1. 書く: 「間違えた過去問だけ解き直せる復習モードがほしい」くらいでよい。「おまかせで作る」を押す。人がやるのはここまで
2. 仕様: エージェントがコード・spec.md・過去の仕様を読んで、`目的／やること／やらないこと／前提と制約／自分で決めたこと` の形にする。持ち主のことばだけでは決められない点は、質問にせず、小さくて後から変えやすい案に決めて理由を残す
3. 凍結: 「## やること」があることを確かめ、`specs/<日時>.md` を main にコミットする。spec.md は全体の前提として計画に一緒に渡る
4. 計画: タスクに分ける。ID は既存の続き（T-019 まであれば T-020 から）
5. 取り込み: 承認の代わりに機械で確かめる（形・ID の重なり・行き先のない依存・依存の輪・1つの仕様から 20 件まで）。通れば「待ち」に入る。通らなければ取り込まずに「計画と承認」に残す
6. 実行: そのまま回す（既定は7時間まで）。ここから先は、安全柵 → ゲート → 独立レビューがこれまでどおり判定する

途中で止まるのは、仕様が仕様の形になっていない・main に未コミットの変更がある・機械の確認に通らない・承認待ちのタスク案が残っている、のどれか。どれも成果物（下書き・タスク案）を残して止まるので、画面から続きをやれる。

自分で読んでから進めたいときは「下書きだけ作る」。下書きは `.hootl/spec-drafts/` に置かれ、まだコミットされない。この道では、決められない点が `決めてほしいこと` に質問として並ぶので、答えを書き込んでから凍結する。

### 設定（`hootl.toml` の `[auto]`）

| キー | 既定 | 中身 |
| --- | --- | --- |
| `approve` | `true` | `false` にすると、下書きとタスク案で止まり、人が凍結・承認する（おまかせのボタンが消える） |
| `run` | `true` | 取り込んだら、そのまま回す。`false` なら「待ち」に入れたところで止まる |
| `hours` | `7` | おまかせで回す時間の上限。`0` で、空になるまで |
| `max_tasks` | `20` | 1つの仕様からこれより多くのタスクが出たら、取り込まずに人に回す |

### ネタ帳

エージェントは、作業の途中で気づいた案を、出力に `::idea {"title": "…", "body": "…"}` の1行として書く（`prompts/ideas.md`）。ハーネスがその行を拾ってネタ帳に移す。仕様の本文には残らない。1回の出力から拾うのは3件まで、同じ名前の案は二度入れない（捨てた案も、もう拾わない）。すでにある案の名前はプロンプトに渡して、同じものを書かせない。

ネタ帳の案が自動でタスクになることはない。作るのは、画面で「これを作る」を押した案だけ。ランのレポートには、その間にネタ帳に増えた案が並ぶ。

CLI なら `hootl auto --idea-file idea.txt` でおまかせ、`hootl ideas` でネタ帳（`add 名前`・`drop 番号`・`build 番号`）。自分で読む道は `hootl spec-draft --idea-file idea.txt --out draft.md` で下書き、`hootl plan specs/xxx.md` で計画（`--approve` を付けると、機械の確認だけで取り込む）。

仕様のファイルが `spec.md` でないプロジェクト（例: モノレポの `apps/web/spec.md`）は、そのプロジェクトの `hootl.toml` の一番上に `spec = "apps/web/spec.md"` と書く。

## setup が作るもの

| ファイル | 中身 |
| --- | --- |
| `~/.config/hootl/web.toml` | ポート・トークン・通すメール・プロジェクトを探す場所（`projects_dir`）。手で `[[projects]]` を足してもよい（setup はそれを残す） |
| `~/.config/hootl/claude-settings.json`（任意・手で作る） | 無人エージェントに渡す権限設定の、自分の環境向けの版。あれば、同梱の `stacks/_common/claude-settings.hootl.json` の代わりに使う。同梱のものを写して、`deny` に守りたい場所（ほかのリポジトリ・秘密のファイル・この hootl-sdd 自身）を足す |
| `~/Library/LaunchAgents/dev.hootl.web.plist` | hootl web の自動起動。ログは `~/Library/Logs/dev.hootl.web.log` |
| `~/.cloudflared/hootl.yml` | トンネルの行き先（`--hostname` のとき） |
| `~/Library/LaunchAgents/dev.hootl.tunnel.plist` | トンネルの自動起動。ログは `~/Library/Logs/dev.hootl.tunnel.log` |

止めるとき: `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/dev.hootl.web.plist`（トンネルも同様）。

## 困ったとき

| 症状 | 見る所・直し方 |
| --- | --- |
| まず何を見ればいいか分からない | `hootl doctor` |
| 画面が固まる・読み込めなくなる | `~/Library/Logs/dev.hootl.web.log` を見る。`Too many open files` が出ていたら、古い版（state.db を要求のたびに開いていた）。更新して `hootl-start.command` を実行し直す。動いている仕事は止まらず、起動し直した画面が引き取る |
| 要対応の理由が「レビュー役が判定を返しませんでした」 | 実装への指摘ではなく、レビュー役（codex）が何も返さなかった。タスクのログの `review.log`・`review-noverdict-N.log` の終了コードと出力を見る。`codex exec` が手元で動くことを確かめてから「やり直す」 |
| 「回す」で起動してすぐ終わる | 回す箱の「出力の末尾」を開く。`command not found: claude` などなら、PATH が足りない。claude が使えるターミナルで `hootl setup` をもう一度実行する（いまの PATH で登録し直す） |
| 準備（node）で全部要対応になる | 自動起動に渡した PATH の node が古い。`nvm use` してから `hootl setup` をもう一度 |
| スマホで 403 | Access のメールと `--email` が一致していない |
| スマホで 502 | Mac 側で hootl web が動いていない（`hootl doctor`）。Mac が寝ていないかも確かめる |
| 「実行中のタスクがあります」で回せない | ターミナルから別に `hootl run` している。そちらを止めるか終わるのを待つ。異常終了の残りなら、次の `hootl run` が自動で待ちに戻す |
| ログインし直したい | ブラウザの cookie（hootl_token）を消す。トークンを変えたら（web.toml の token を消して `hootl setup`）全員ログアウトになる |
