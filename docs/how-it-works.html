作りたいものを書くと、マージ済みのコードが出てくる。人が立つ持ち場は3つだけ。

hootl は、AI エージェントにタスクを1件ずつ渡し、テストとレビューで合否を決めて、通ったものだけを main に入れるライン。落ちたら理由を添えて差し戻し、3回落ちたらラインから外して朝の人に回す。止まらずに夜通し動く。

1タスクの中で起きること。「終わった」はモデルではなく判定が決める

1準備

main から worktree を切り、依存を入れ、使い捨てのテスト用 DB をまっさらにする。

落ちたら: 環境の問題なので、すぐ要対応へ

2実装

Claude Code がタスクと受け入れ条件を受け取り、コードとテストを書く。依存の追加やスキーマ変更もしてよい（理由を残す）。

落ちたら: 異常終了なら差し戻し

3安全柵

判定する側（lint・型・テストの設定、CI、規約）を触っていないか、テストを無効にしていないかを機械で見る。

落ちたら: 違反の一覧を添えて差し戻し

4ゲート

lint・型チェック・テスト・ビルドを上から順に。全部が終了コード 0 なら通る。

落ちたら: 出力の末尾を添えて差し戻し

5レビュー

別ベンダーのモデル（Codex）が、差分と受け入れ条件を突き合わせる。盲点が重ならないように別の目にする。

落ちたら: 指摘を添えて差し戻し

6マージ

main に入れて push。ほかのタスクとぶつかったら、最新の main から作り直す。

落ちたら: 衝突として差し戻し

外から触る道。鍵は2本、入口は1つ

1日の回し方

いつ人がやることライン
始めるとき「＋ 新しいアプリ」で作りたいもの・型（Web／スマホ／バッチ／Cloudflare Workers）・オプション・ゲートを選んで「作る」フォルダ・git・依存・全ゲート・起動確認・最初のコミット・仕様まで進み、そのまま計画 → 実装へ続く。ゲートは型ごとに共通の部品
思いついたとき管理画面の「仕様」タブに作りたいものを数行書いて「おまかせで作る」。または「ネタ帳」から選んで「これを作る」（持ち場 1）。Mac はスリープさせない仕様を書いて凍結し（specs/ に入り main にコミット）、タスクに分け、機械で確かめて「待ち」に入れ、そのまま回す。待ちから1件ずつ取り、通れば main に入れて push
朝要対応だけ見る。ログで原因を確かめ、タスクを直すか、割るか、捨てる（持ち場 2）。ネタ帳に増えた案を読むレポートが1本増えている。途中で見つけた案がネタ帳に並んでいる
機械の確認で止まったとき「計画と承認」に残ったタスク案を直して取り込む（行き先のない依存・件数が多すぎる、など）取り込まずに待っている
出すときmain を触って確かめ、ストアや本番に出す（持ち場 3）—

動かし方。始めるのは1コマンド

設定ファイル、トークン、自動起動、ブラウザで開くまでを hootl setup がやる。何度実行してもよく、あるものは残して足りないものだけ作る。

1. 手元で使い始める

道具を確かめ、設定を作り、Mac にログインしたら自動で起動するよう登録して、ブラウザで開く。トークンはクリップボードに入るので、貼り付けて入る。

cd ~/hootl-sdd && python3 -m pip install -e '.[dev]'
hootl setup

2. スマホからも使う

1回目は Cloudflare Access（門番）の作り方を出して止まる。門番ができるまで外には出さない。作ったら --access-ready を足してもう一度。

hootl setup --email 自分のメールアドレス --hostname hootl.example.com
hootl setup --email 自分のメールアドレス --hostname hootl.example.com --access-ready

3. 様子がおかしいとき

道具・設定・見つかったプロジェクト・画面の応答・トンネルを一覧する。

hootl doctor

プロジェクトは ~/hootl-runs/ の下の専用 clone から自動で拾う。増やしても設定は直さなくてよい。寝ている間も回すなら、電源につないだ Mac がスリープしない設定にしておく。詳しくは hootl-sdd の docs/web-admin.md。
